# Experimental simulation world

`SimulationWorld` is a build-tree-only Phase 17 prototype, not an installed API or a compatibility guarantee. A world owns a bounded list of dynamic spheres and a fixed timestep. `addSphere` copies its input and returns a world-local identifier; zero indicates an invalid body, exhausted capacity, or exhausted identifiers. Identifiers are not interchangeable between worlds and are not reused within a world. `removeSphere` removes a live identifier, returns false for an invalid or stale identifier, and frees capacity for a new body without changing surviving identifiers. `getSphere` copies state into the caller's output on success and leaves it unchanged on failure. Calls are single-threaded; concurrent access and removal during `step` are unsupported.

Coordinates are meters, velocity is meters per second, gravity is meters per second squared, and Y is up. Each `step` advances exactly one configured interval using semi-implicit Euler. The caller owns the wall-clock accumulator and interpolation. Inputs must be finite, the timestep and sphere radii positive; invalid construction throws `std::invalid_argument`. A non-finite intermediate result makes `step` return false without changing any body. Choose sensible scales and timesteps: finite arithmetic can still lose precision, and the prototype does not enforce a stability limit.

The only contact is an infinite stationary floor at Y=0. After integration, a sphere whose center is below its radius is projected onto the floor and its downward vertical velocity is set to zero. This is a simple inelastic floor constraint, not continuous collision detection or a general contact solver. Initial overlapping bodies are corrected on the first step. Spheres do not collide with each other. Rotation, forces, mass, friction, restitution, sleeping, broadphase, threading, streaming, and replay are not implemented. Results are not guaranteed identical across compilers or platforms.

Capacity is reserved on construction; this is not a measured zero-allocation or performance guarantee. PC and Android measurements remain outstanding. Run `test_simulation_world` and `simulation_world_example` through CTest in the build tree. Rendering, input, and gameplay remain the host application's responsibilities.

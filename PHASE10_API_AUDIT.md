# Phase 10 Module API Audit

## Scope

This audit compares the eight pinned sibling repositories listed in
`dependencies/PhysicsCoreRepos.cmake` with the sources aggregated by
`CMakeLists.txt`. The pinned revision is the CI source of truth.

`PHASE10_API_INVENTORY.md` is the generated parser-aware function inventory.
Regenerate it with:

```powershell
./scripts/audit-c-api.ps1 -ReposRoot D:\repos
```

Phase 10.1 adds `PHASE10_API_CATEGORIES.md`, generated by the same command.
It assigns all 811 declarations to one planning category: lifecycle/state,
export-file, array/matrix/state, numerical-solver, buffer-or-enumeration, or
scalar-domain. These are review groups, not proof of scientific correctness.
Phase 10.2 adds `PHASE10_API_TEST_PLAN.md`, which compares those declarations
with exact references in `tests/*.cpp` and identifies the next test batches.

## Findings

1. All eight module C API implementation files are included in the aggregate
   `PhysicsEngine` static library through their object libraries.
2. Seven modules provide their C API declaration header in the pinned sibling
   repository. FluidDynamicsCore provides no `fluid_c_api.h` at the pinned
   revision.
3. The project-owned `fluid_c_api.h` is therefore the deliberate public
   declaration boundary for the five compiled Fluid wrappers:
   `fluid_hydrostatic_pressure`, `fluid_bernoulli_velocity`,
   `fluid_reynolds_number`, `fluid_speed_of_sound`, and `fluid_mach_number`.
4. QuantumCore's pinned C API declares two member functions absent from the
   pinned `QuantumParticle.cpp`. `QuantumParticleCompatibility.cpp` supplies
   those definitions in this repository, preserving the exposed wrappers
   without modifying the sibling repository.
5. The existing `PhysicsEngine.h` aggregates all eight module C APIs. The
   collision headers under `include/physics` are a separate C++17 API and are
   not part of the module C ABI.

## Current equation coverage

`tests/test_fluid_api.cpp` provides reference-value and safe boundary checks for
all five stateless Fluid wrappers. `tests/test_engine_integration.cpp` provides
representative reference checks for:

- Quantum delta-potential energy;
- Classical projectile position;
- Electrodynamics Coulomb force and wave speed in a medium;
- Optics Snell refraction and thin-lens image distance;
- Solid-state Bragg angle; and
- Thermodynamics ideal-gas pressure.

The same integration test also checks Solid State kinetic thermal conductivity
and Landauer conductance against their reference equations.

The current integration coverage also checks Thermodynamics ideal-gas volume,
isothermal work, Carnot and Otto efficiencies, entropy change, Helmholtz free
energy, and enthalpy. Optics coverage includes total-internal-reflection
behavior, critical and Brewster angles, magnification, and spherical-mirror
focal length.

Electrodynamics coverage includes Coulomb potential, dipole torque, Gauss-law
flux, capacitor energy, Ohm's law, and wave speed in a medium. Nuclear coverage
includes SEMF binding energy, nuclear radius, pairing delta, and the explicit
invalid-charge binding-energy result of zero.

Quantum coverage also includes particle mass, harmonic-oscillator energy,
Hermite polynomial values, and ground-state position/momentum uncertainties.
Classical coverage includes free-particle kinetic energy and simple harmonic
oscillator position, energy, and period.

Array-output coverage now checks Quantum one-dimensional-box wavefunction length
and values, Quantum Pauli-X matrix serialization, and Nuclear SEMF curve output.
The Nuclear test confirms that the wrapper returns at most the caller-provided
buffer length and reports the truncated count.

The pinned Quantum implementation currently uses `hbar = 1.0` for its
harmonic-oscillator energy helper, while its wavefunction and uncertainty
helpers use the physical `hbar` constant; tests preserve and document this
observed implementation behavior.

The existing integration test also verifies lifecycle and one representative
call for every module. This is representative coverage, not yet exhaustive
coverage of every declaration in the large sibling C APIs.

## Phase 10 actionable gap

The parser-aware inventory task is complete with zero declaration/definition
mismatches across all eight APIs. Remaining work is grouped reference testing
for the remaining declarations, especially stateless mathematical helpers and
lifecycle-safe stateful operations. The inventory does not itself prove
scientific correctness or define behavior for invalid numeric domains.

Scientific review is needed for two pinned Thermodynamics implementations:
`ThermoSystem::debyeSpecificHeat` does not appear to approach the standard
high-temperature limit of 3 nR, and `debyeEntropyLowT` appears to use the
low-temperature heat-capacity coefficient rather than the entropy coefficient.
Verify against authoritative references and correct in ThermodynamicsCore before
claiming these APIs are scientifically validated; neither is covered by the
new reference tests.

`SolidStateSystem::debyeSpecificHeat` returns `9 R * D3(thetaD/T)` and thus
approaches 9 R rather than the standard 3 R per mole at high temperature.
Review its full temperature dependence and correct it in SolidStateCore before
claiming `ss_debye_specific_heat` is scientifically validated.

`ThermoSystem::ising1DMagnetization` ignores its `N` argument and implements
the infinite-chain magnetization per spin. Clarify that contract or implement
the finite-chain result in ThermodynamicsCore before validating this API.

`ClassicalParticle::drivenHOPowerAbsorbed` uses half the mean power expected
for the oscillator's `2*gamma` damping convention. Review the factor of two
in ClassicalMechanicsCore. Its driven-time CSV also labels `F0/mass` as
`driving_force`; clarify the units or correct the exported value.

`NuclearSystem::computeBetaSpectrum` evaluates its Fermi factor as 0/0 for
`Z == 0`, although the zero-charge limit is 1. Review and correct this case
in NuclearCore. `np_export_bethe_bloch_csv` fixes the excitation energy at
78 eV regardless of target and omits density-effect corrections; clarify the
applicable approximation and allow target-specific input where needed.

`em_export_transmission_line_csv` accepts `ZL` but ignores it and sweeps a
fixed 1–201 ohm load range instead. Clarify or revise this argument in
ElectrodynamicsCore; the CSV reference checks the current sweep behavior.
`em_export_circ_waveguide_csv` ignores its point-count argument and always
exports 15 modes. Its reference checks this observed behavior at two counts;
clarify or revise the argument in ElectrodynamicsCore.

`EMField::eddyCurrentDensity` computes `B0*omega*delta*exp(-z/delta)/2`,
which has electric-field units in SI rather than current-density units.
Review the intended quantity and conductivity dependence in ElectrodynamicsCore.

`EMField::metamaterialPermittivity` takes the real part of its complex
denominator before division, so its damping argument has no effect. Review
against the intended complex Drude response and correct in ElectrodynamicsCore
before claiming the exposed API is scientifically validated.

For positive electron density, `em_export_plasma_csv` sweeps frequencies below
the plasma frequency, where `plasmaGroupVelocity` takes the square root of a
negative value. Those CSV rows can contain non-finite group velocities. Review
the evanescent-wave representation and export contract in ElectrodynamicsCore
before validating this export; this finding is based on source inspection.

`EMField::synchrotronPower` uses a charge-squared, gamma-to-the-fourth and
inverse-cubed-speed expression for a magnetic field input. Its dependence on
charge, gamma and speed of light differs from the Lienard formula with magnetic
acceleration substituted. Review the intended units and expression in
ElectrodynamicsCore before validating its scalar wrapper or CSV export.

The Quantum header labels `qp_two_level_perturbation` and `qp_two_level_exact`
outputs as E_minus then E_plus, but their pinned implementations return the
positive branch first and negative branch second. Correct the sibling header
or version the API deliberately rather than silently changing the output order.

`qp_free_electron_transition` labels its second output `outDeltaE` and calls it
transition energy, but the implementation writes the wavelength `h*c/gap`.
Clarify or version the sibling contract before changing that output's units.

`qp_rabi_probability` divides by the effective frequency and returns a
non-finite result when both drive and detuning are zero. Review and correct
the zero-drive limit in QuantumCore; the expected transition probability is zero.

`qp_barrier_rt` divides by zero at the positive-energy threshold `E == V0`,
producing non-finite coefficients rather than the finite rectangular-barrier
limit. Correct the threshold calculation in QuantumCore.

`qp_transfer_matrix_multilayer` also divides by zero when a layer height equals
positive incident energy: its evanescent branch evaluates `sinh(0)/0` instead
of the finite zero-wave-number limit. This also affects
`qp_resonant_tunneling` when its barrier height equals the energy. Review and
correct these threshold cases in QuantumCore; the added tests avoid them.

`qp_breit_rabi_energy` uses a zero-field offset of `-DeltaHF/[4(2I+1)]`;
the standard Breit-Rabi expression uses `-DeltaHF/[2(2I+1)]`. Review the
energy convention and correct the offset in QuantumCore if appropriate.

`qp_coulomb_energy` uses a prefactor proportional to `e^2/epsilon0^2/hbar^2`,
which differs dimensionally and numerically from the hydrogenic `e^4` formula.
Verify and correct the QuantumCore implementation before scientific validation.
`QuantumParticle::hydrogenRadialWavefunction` uses a cubic `(n+l)!` factor in
its normalization while its associated Laguerre polynomial uses the standard
recurrence. Review the normalization for excited states in QuantumCore; the
CSV reference test covers only the unaffected 1s state.
`qp_double_delta_energy` ignores the separation `a` and returns a single-delta
energy under a simplified approximation; review its validity and document its
applicable domain before treating it as a double-delta reference.
The compatibility implementation of `qp_delta_potential_wavefunction` ignores
`n` and computes the single attractive-delta bound state for positive strength;
clarify the supported state and numeric domain in the public API.

For `qp_two_particle_isw` with equal quantum numbers, the symmetric expression
has a factor of `sqrt(2)` relative to the normalized product state. Review its
normalization in QuantumCore; the added exchange checks use distinct levels.

`qp_export_spin_analysis_csv` divides probabilities by the spinor norm but
does not normalize the reported spin expectation values. A zero spinor also
causes division by zero. Clarify or correct the contract in QuantumCore; the
CSV reference uses a normalized nonzero spinor.

`qp_coherent_state_photon_prob` evaluates `0 * log(0)` for zero coherent-state
amplitude and photon number zero, producing a non-finite result instead of the
vacuum probability one. `qp_export_coherent_state_csv` calls the same function;
review the zero-amplitude limit in QuantumCore. This is a source-based finding.

At zero time the pinned free and harmonic propagator magnitude APIs return
zero as an implementation sentinel. The harmonic propagator also returns zero
when `abs(sin(omega*t)) < 1e-30`. These singular kernel values require a
documented distributional interpretation rather than a physical zero claim.
